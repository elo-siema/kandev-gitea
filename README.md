# kandev-gitea

A [Kandev](https://github.com/kdlbs/kandev) plugin that connects one Gitea
instance to Kandev's native code-host surfaces:

- **Repository provider** — pick Gitea repositories and branches in the task
  dialog, paste a Gitea repository URL, and clone/push with the configured
  token through Kandev's Git credential broker.
- **Pull requests** — create a PR (optionally as a `WIP:` draft) after Kandev
  pushes a task branch; link or unlink an existing PR from the task **Link**
  menu using `owner/repo#42` or a PR URL.
- **Review status** — task indicators, CI chip, and the shared Review panel
  driven by Gitea commit statuses, reviews, and requested reviewers.
- **Composer `#` references** — search pull requests across the instance;
  every reference is re-authorized against Gitea before a prompt is sent.

The plugin id is `kandev-plugin-gitea`; the provider id is `gitea`.

## Requirements

- Kandev **0.94.0** or newer (the release this plugin is built and tested
  against).
- A Gitea instance served over **HTTPS**. Kandev only accepts HTTPS provider
  origins and clone URLs. Sub-path installs (`https://example.com/gitea`) work.
- A Gitea access token with `read:user`, `read:repository`,
  `write:repository`, and `read:issue` scopes. It is used for the API and as
  the Git credential, so it decides what the plugin (and task agents) can do.

## Install and configure

1. Build a package (below) or download one from the releases page.
2. **Settings > Plugins > Install plugin**, upload the tarball, then enable
   **Gitea**.
3. **Settings > Plugins > Gitea**: set **Gitea URL** and **Access token**.
   The token is stored in Kandev's encrypted vault and never shown again.

Settings are instance-wide: every workspace uses the same Gitea connection.
Task ↔ pull-request links are kept in workspace-scoped plugin state.

## Develop

`go.mod` and `package.json` resolve the Kandev SDK from a sibling checkout,
exactly like the official template:

```text
parent/
├── kandev/          # https://github.com/kdlbs/kandev at v0.94.0
└── kandev-gitea/    # this repository
```

```sh
npm ci
make vet
make test                 # vitest + go test
make build                # bundles ui/bundle.js and builds bin/kandev-plugin-gitea
make package-host         # tarball for this platform (fast)
make verify-package       # all five platforms, checksums verified
```

`ui/bundle.js` is generated by esbuild from `ui/src` and is committed because
Kandev ships it byte-for-byte; CI fails when it is stale.

## Release

Bump `version` in `manifest.yaml` and `VERSION` in the `Makefile`, then push
a matching tag (`v0.1.0`). The release workflow packages every platform and
publishes the tarball plus `checksums.txt` as a GitHub Release.

## Layout

```text
manifest.yaml            plugin identity, actions, provider/reference declarations, settings schema
server/                  pluginsdk.Serve entrypoint and wiring
internal/sourcecontrol/  provider-neutral recipe from kandev-plugin-template (+ review detail payload)
internal/gitea/          Gitea REST client, recipe adapters, task links, Git credentials
ui/src/                  register.ts recipe, Gitea mapping, icon, bundle entry
ui/test/                 vitest suites
assets/icon.svg          official Gitea logo (see assets/NOTICE.md)
```

## Limitations

- Personal access tokens only; no OAuth flow and no per-workspace connections.
- Drafts use Gitea's `WIP:` title convention.
- The Review panel shows metadata, reviews, and checks but not review comments.
- `#` search returns Gitea's issue-search results for pull requests
  (`state=all`), so closed PRs appear too.
